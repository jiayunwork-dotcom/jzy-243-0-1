我在一家化工厂做过程控制。厂里有不少大纯滞后的回路，比如长管线末端的浓度、换热网络下游的温度，滞后动辄是时间常数的一两倍，普通 PI 调得稍快就振荡。我们开始在这些回路上用 Smith 预估器，但每条回路的 PI 参数仍然靠现场试，试一次就是一个班。我想先有一个离线整定工具：工程师在网页上填对象模型和搜索范围，后台扫一遍参数，找出在模型有偏差时也稳得住的那一组。

被控对象用一阶加纯滞后描述：增益、时间常数、滞后时间。控制器是 PI 加 Smith 预估器，预估器内部的模型可以与真实对象不同，用来模拟建模误差。仿真给出设定值单位阶跃下的输出、控制量和误差曲线，并算出超调量、调节时间（进入并保持在 ±2% 带内）、误差绝对值积分。可以核对的性质：预估器模型与对象完全一致时，闭环设定值响应恰好等于去掉滞后之后同一 PI 回路的响应整体右移一个滞后时间，二者逐点相同（在离散化误差内）；纯比例控制、无滞后时稳态误差为 1/(1+比例增益×对象增益)；加入积分后稳态误差趋于零。

整定以"扫描作业"进行：给定比例增益和积分时间的范围，以及一组模型失配情景（例如滞后偏大 20%、增益偏小 15%），对每一组参数在所有失配情景下仿真，以最坏情景的指标为准。约束是最坏超调不超过给定百分比、所有情景都能在仿真时长内稳定，在满足约束的参数里取最坏误差积分最小的一组。有的参数在某个失配情景下发散，要识别出来并排除，不能让数值溢出污染结果。搜索是全网格硬扫，还是先粗后细逐步收窄，离散化方式和步长怎么取，由你取舍并在文档里说明对结果可信度和耗时的影响。

作业异步执行，能看进度、能取消；设了时限的作业到点后返回当前已知最优解并注明未扫完。作业的输入、每个网格点的指标和最终结果都存库，同一输入重复提交直接复用已有结果；服务重启后未完成的作业从中断处继续，最终结果与不中断时一致。

前端是表单页：录入对象模型、预估器模型、失配情景和搜索范围，提交后看进度；完成后展示最优参数，以及所选参数在各个失配情景下的阶跃响应曲线和指标表，允许点选网格中任意一点查看其曲线。

需要拒绝：增益为零、时间常数非正、滞后为负、积分时间非正、搜索范围上下界颠倒、仿真时长不足滞后的两倍。

后端 Go 1.23 + chi，前端 React 18 + Vite，作业与网格结果写 MySQL 8.0，数据库容器用 mysql:8.0；后端用 golang:1.23-alpine 编译。前端、后端、数据库三个容器放进同一份 compose 里一起起。仿真内核、性能指标、扫描调度、作业持久化、HTTP 接口和前端页面分开组织；go test 覆盖模型一致时的平移等价、比例控制稳态误差、发散点识别、约束筛选、重复提交复用、重启续扫一致，前端至少有表单校验的测试。
